Equipment — 6 slots

Six positions (Left Top / Left / Left Bottom / Right Top / Right / Right Bottom). 162 items, 27 per slot, qualities 1–7, stars 0–5. In-game names like Tactical Helmet / Vest / Pants / Gloves / Wrist Guards / Boots.

Attachment & Drone Enhancement

Both track a 7-queue × 50-level ladder with identical cost curves: - Queues 1–4 (common→rare): cost 2, 3, 5, 7, 10, 15… 950 (item count) - Queues 5–7 (advanced tier): cost 1, 1, 2, 2, 3, 3… up to 30 — far cheaper for late gear

Takeaway: the higher-tier queues are the most coin/material-efficient; push those.

World Phases & Function Unlocks

  • World Phases by server day: Day 8 → Level 1 Cities, Day 16 → Level 2 Cities, Day 24 → Level 3 Cities (higher-tier cities = better idle/alloys).
  • Function unlock conditions are primarily player level / stage queue / server days, so progressing the campaign fast is what opens systems sooner.
  • The in-game "Get Stronger" ordering (its Priority guide) tells you the intended power path:

Weapon → Tactics (Talents) → Attachment → Drone → Equipment

This is a solid spending order early on: weapon level/enhance gives the most immediate DPS, equipment is the % endgame payoff.

Spending Priorities (summary)

  1. Keep weapon level + enhancement on your main weapon (biggest DPS per coin/module).
  2. Unlock Weapon Spec capstones and spread talent stars broadly.
  3. Forge Q5+ equipment (Alloy is scarce — save it).
  4. Push stages to raise idle Coin (your main income).
  5. Take the idle quick-claim before the 8 h cap, and buy energy only when pushing a stage.

Enemies, Stages & the World

Zombie Roguebie (v1.20.0) is a wave-survival shooter. This section covers the enemy roster (with relative HP/ATK), the boss lineup, campaign progression and its hidden difficulty scaling, tower/explore/world structure, and what enemies drop.

How to read the numbers. Monster HP/ATK is stored as a multiplier on the stage's base. Below, "×N" means N× the stats of a baseline mob of that stage. So a ×50 Elite is 50× tougher than the ×1 trash walking beside it, and a boss is another order of magnitude on top. ATK scales identically to HP for every enemy in the game.

  • Boss rewards also gate material drops used for attachment/module crafting.

Zombie Roguebie — Code / Schema Reference

Package com.boom.zombie.survival v1.20.0 · Unity/HybridCLR.

How this section was recovered. The four target assemblies (GameProto, TouchGame, TouchEngine, xasset) are .NET/HybridCLR assemblies that the game obfuscates: all four have a corrupt PE (the e_lfanew pointer is zeroed, the optional-header magic and the section table are garbage) and the .NET metadata root's stream-header offsets/sizes are encrypted (they serialize to huge junk like 0xabb2ed38). dnfile, pefile, ilspycmd and dotnet's manager all refuse to open them. So no IL / method bodies could be decompiled. The meanings below come from the clean JSON config tables, the embedded field-name strings that survive in plain text (e.g. <WeaponATKRate>k__BackingField, get_HPRate, CheckInstantKill, CalcDamage), and a prior decode of extract/.

1. Weapon.json — Attrs array and WeaponATKRate

Attrs is a 4-element array of strings (the four stats shown on a weapon card), in this fixed order:

Index Meaning Notes
Attrs[0] ATK / damage multiplier e.g. M5 = 3.6, MP9 = 5.0, Sniper M24 = 1.0, RPG = 0.6. Matches the in-game "Attack" tips label (item_weapon_tips_txt_atk_title). This is the per-shot damage coefficient.
Attrs[1] Fire interval (seconds between shots) Fast weapons ≈ 0.40–0.80 (M5 0.40, MP9 0.45), slow ≈ 1.20–1.55 (M24 1.20, RPG 1.50), slowest — the special snipers — 4.00 (Frost Beacon, Thor). "Lower = faster". UI stat is titled "Fire Rate".
Attrs[2] Per-class damage/crit multiplier Groups cleanly by weapon class: Shotgun 5.5, Submachine 6.0, Assault/HMG/Rocket 6.5, Sniper 7.0. Most plausibly the weapon's Crit Damage multiplier (sniper hits hardest on crit). Exact label could not be confirmed from obfuscated IL.
Attrs[3] Magazine capacity Matches ClipCapacity exactly in all 16 weapons (M5=12, MP9=20, M24=3, M2HB=40, RPG=2 …).

WeaponATKRate — a per-weapon "attack-rate / ATK" multiplier, present as a field but 0 for every weapon in v1.20.0. It is effectively inert (a placeholder/legacy argument; the real damage coefficient lives in Attrs[0]). The weapon itself instead grants a flat stat: OwnedAttr = { ID: 1012, Value: 200–300 }, where 1012 = "Attack Bonus" (enum ATKRate) — the weapon carries a small permanent ATK-bonus attribute.

Weapon damage also scales with level/rank, not just Attrs[0]: - WeaponLevel.json defines per-level WeaponATKBase (1 → 100, 10 → 200, 20 → 400, 50 → 2500, 100 → 10000, 1000 → 1,000,000 — roughly Level² at high level). - WeaponRank.json adds a rank bonus WeaponATKBase (rank 1 → 20, rank 5 → 80, rank 15 → 6000) and a rank Cost.

So a weapon's effective per-shot damage ≈ WeaponLevelBase × WeaponRankBonus × Attrs[0] (fit to the gun's class), plus flat/elemental bonuses.

2. Monster.json — HPRate / ATKRate / DropItem / InstantKillRatio / RepulseRatio

Scale: 10000 = 1× for HPRate and ATKRate (integer centi-per-mille). InstantKillRatio and RepulseRatio are plain 0–1 floats. Values per strength tier:

Type Strength Example HP× ATK× InstantKill Repulse DropItem
Normal 1 Monster 1.0 1.0 1.0 0.9 1
Normal 5 Monster 5.0 5.0 1.0 0.4 2
Normal 30 Monster 20.0 20.0 1.0 0.0 2
Elite 50 Monster 50.0 50.0 0.5 0.0 3
Elite 75 Monster 75.0 75.0 0.5 0.0 3
Boss 500 Furious Zombie King 350.0 350.0 0.5 0.0 3
  • HPRate = multiplier over the monster's base HP: effective HP = baseHP × (HPRate/10000). It tracks Strength directly (a strength-50 elite = 50× the strength-1 base; a strength-500 boss ≈ 350×).
  • ATKRate = multiplier over the monster's base attack: damage dealt to player = baseATK × (ATKRate/10000). In the file ATKRate is always identical to HPRate for a given monster (they scale together).
  • InstantKillRatio = the execute threshold — the fraction of the monster's max HP at or below which an instant-kill can trigger. Scrap mobs (strength ≤ 30) = 1.0 (executable from full HP); elites/bosses (strength ≥ 50) = 0.5 (only under 50% HP). It is a boss-protection wedge. Core methods: CheckInstantKill, CheckSpecialHitInstantKill, get_InstantKillRatio.
  • RepulseRatio = knockback / repulse magnitude applied when the monster is hit (0 = knockback-immune). Regular mobs have 0.08–0.9 (pushable); all elites and bosses are 0.0 (crowd-control immune). Core: get_RepulseRatio.
  • DropItem = the ID of a death-drop template in DropItem.json (what spawns when it dies), not a boolean and not a rolled list. Trash mobs use template 1 (exp orb worth 10) or 2 (exp orb worth 30) or none; a couple use 9991 (exp worth 15000); every elite and boss uses template 3.

3. Final damage computation + are drops rolled or guaranteed?

The exact coefficient ordering lives in the obfuscated CalcDamage method of TouchGame.dll, which could not be decompiled, so the combination formula is UNKNOWN. The recovered damage schema is:

Player → monster, per hit/instance: - Weapon base damage = WeaponLevelBase (≈ Level² + rank bonus) × Attrs[0] (gun coefficient). - Fire cadence from Attrs[1] (interval); magazine from Attrs[3]. - Crit: roll against Crit chance (Attr 1030); on crit multiply by CritDamage (Attr 1040, base 15000 = 1.5×; weapon-side in Attrs[2]). - Elemental damage types (Attr ids): Firearms 1091, Shrapnel 1092, Ice 1093, Electric 1094, Fire 1095 (element IDs: 1 Firearms, 2 Shrapnel, 11 Ice, 12 Electric, 13 Fire). Each has a matching resistance on the target: 1191–1195. Attr 1060 = "Final Damage" is the post-mitigation value. - Target-state modifiers (from BattleParam / code strings): TargetInRangeFinalDamage, TargetFreezeFinalDamage, TargetBurnFinalDamage, BulletPierceFinalDamage — extra multipliers applied to targets that are in-range, frozen, burning, or pierced. Global off-hand modifiers: BurnDamageRate, BurnExplosionDamageRate, FrostbiteDamageRate, FieldDamageRate, WheelDamageRate, RecurrectSkillDamageRate.

Monster → player: baseATK × ATKRate/10000, mitigated by the player's shield/defense (Shield attr 1020, regen time attr 1070) and dodge/iframes (DodgeInvincibleTime, BeDamageInvincibleTime).

Drops — guaranteed, not weight-rolled. Monster.DropItem is a single fixed template reference (no array of weighted entries), so the death-spawn always fires the same template for that monster ID (and is absent for monsters with DropItem = null). The templates in DropItem.json are deterministic: - Func=1 → an experience orb worth FuncParam (10 / 30 / 15000). - Func=2 → a generic loot spawn (used by all elites/bosses). - Func=4 → an item drop with a quality-coloured FX (ShowPropName) — white/green/blue/purple/gold/red/pink (IDs 1000–1007).

Weighted probability rolls only appear in the chest/gacha tables (TurntableReward has Weight/ShowWeight), not in monster kills. So: kills are guaranteed, fixed drops; rarity is decided by the item/prop quality system, not by a per-kill weight.
